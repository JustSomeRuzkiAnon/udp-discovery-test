# Проверка входящего UDP на ONREZA

Приложение проверяет, может ли публичный UDP-пакет дойти до процесса Compute и какой IP и порт отправителя увидит сокет. Приёмник записывает идентификатор тестовой пробы и адрес отправителя в лог приложения.

## Деплой

1. Подключите этот репозиторий и ветку `main` в ONREZA. Укажите корень сервиса `.` и пресет **Go HTTP**. Оставьте стандартную команду Go-сборки. Если в проекте задан выходной каталог вручную, укажите `build/onreza-go`. Стандартная сборка создаёт в нём бинарник `server`, указанный в `onreza.toml`. Приложение слушает HTTP на порту из переменной `PORT`. [Документация по Go](https://docs.onreza.ru/projects/frameworks)
2. Если ONREZA позволяет направить публичный UDP на отдельный порт процесса, задайте этот внутренний порт переменной `UDP_PORT`. По умолчанию приложение слушает TCP и UDP на одном номере порта из `PORT`.
3. По HTTPS откройте `/healthz`. Поле `udp_listening: true` подтверждает открытие UDP-сокета внутри процесса. Значение `udp_port` показывает внутренний порт. Для проверки из интернета нужен публичный адрес и порт UDP, опубликованные для деплоя.

## Проверка

Откройте `/healthz` перед отправкой, чтобы процесс был запущен. С машины вне ONREZA отправьте UDP-пробу на выделенный вашему деплою публичный UDP-адрес и порт. Скрипт работает на Python 3 без дополнительных пакетов.

```sh
python probe.py PUBLIC_UDP_HOST PUBLIC_UDP_PORT
```

Чтобы использовать конкретный исходный порт, добавьте `--local-port 51820`. В выводе будут локальный порт и `probe_id`. Найдите этот ID в логах приложения. Ожидаемая строка выглядит так.

```text
udp_probe id=0123456789abcdef0123456789abcdef source_ip=203.0.113.42 source_port=43023
```

- Совпавший ID подтверждает доставку UDP. `source_ip` и `source_port` — значения, которые увидел сокет. Для проверки сохранения адреса сначала отправьте пробу с машины с известным публичным IPv4 и явно заданным локальным портом.
- `udp_listening: false` означает, что сокет не открылся или перестал читать пакеты. Причину показывает строка `udp_bind_error` или `udp_read_error`.
- Если сокет открыт, а ID в логах отсутствует, проба не дошла до приёмника по проверенному адресу и порту. Публичный HTTPS-адрес сам по себе не подтверждает наличие UDP-маршрута.
